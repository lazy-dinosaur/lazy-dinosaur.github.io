# 웹사이트는 어떻게 보여지는가

웹사이트는 [[웹사이트에 들어갈때에는 어떤 일이 생기는가|사용자의 요청]]에 따라 [[웹사이트는 어떻게 구성되어있나|웹사이트를 구성]]하는 [[HTML]]과 [[CSS]] [[Javascript]]를 전달받고 이 파일들을 *브라우저가 이해하고 렌더링*하는 과정을 거쳐 눈에 보여지게 된다.

## 브라우저의 렌더링 과정

브라우저는 HTML 과 CSS를 바로 이해하지 못한다 따라서 이해하고 화면에 그릴 수 있도록 하는 일련의 과정을 거친다. 그리고 이 과정을 *Critical Rendering Path*라고 부른다.

첫번째로 브라우져는 서버로 부터 받은 *HTML을 파싱하여 점진적으로 DOM(Document Object Model)을 생성*한다. 파싱 과정은 첫줄부터 순차적으로 진행되며 파싱하는 도중 `<link rel="stylesheet">`태그를 만나면 CSS 파일을 요청하고 파싱하여 *CSSOM(CSS Object Model)을 생성*한다.

위의 *두 작업은 병렬로 처리*된다. 작업이 진행되는 도중 *`<script>` 태그를 만나게 되면 HTML은 즉시 파싱을 일시 중단*하고 CSS 의 경우 이전까지 *파싱하던 곳 까지의 CSSOM생성을 완료한 이후 일시 중단*한다.

Javascript 처리가 끝나면 중단 시점부터 HTML 과 CSS의 파싱이 재게된다.

또한 HTML 파싱과 CSS 파싱은 둘 다 *점진적으로 진행*되며 일정부분까지 DOM생성이 되었고 해당 부분까지 필요한 CSS 파싱이 처리되어 CSSOM이 생성되었다면 두 트리를 합쳐 *Render Tree를 생성*하는데 이때 화면에 표시되지 않는 요소들을 배제한다(ex: display:none)

이렇게 부분 부분 처리하며 특정 부분의 렌더트리가 생성이 됬다면 _Layout_ 단계를 거쳐 Render Tree의 노드와 그 관계되는 각 요소들이 화면에 위치해야 하는 위치와 크기를 설정하고 _Paint_ 단계로 넘어가 Render Tree의 각 노드를 화면에 그리게 된다. 이때 색상, 이미지, 그림자 등 시각적 요소가 처리된다. 이때 노드들간의 관계를 이해하고 표현하기 때문에 필요에 따라 여러 레이어를 형성하게 된다

이후 *Compositing*을 통해 만들어진 페이지 레이어들을 합성한다. z-index가 적용된 우선순위에 따라 레이어 우선순위가 정해진다.

# 괴담집 이야기 생성 워크플로우 구축

## 목표

n8n과 claude api를 활용하여 공포이야기를 **생성**, **정제**, **저장** 하는 워크플로우를 만든다.

## n8n 의 기본 설치

n8n의 실행 방법은 두가지로 `npx`를 사용하는 방법과 `docker`를 사용하는 방법 두가지가 있다.

후에 테스트가 끝나고 n8n을 OCI에 올릴 때에는 docker를 사용할 예정이지만 테스트를 위해서 `npx`를 통해 빠르게 시작해 보도록 한다.

```bash
npx n8n
```

> [!info]
> n8n의 기본 설정 파일 경로는 `~/.n8n/config`에 위치한다.

## 1. n8n의 기본 구조

![n8n-workflow](_assets/attachments/괴담집/n8n-workflow-screen-1.png)

n8n을 처음 실행하고 아이디를 만들고 로그인 하면 최초 워크플로우를 만들어 볼 수 있다.
구조는 매우 단순하다. 마우스로 클릭 만으로 노드들을 추가하여 서로 연결할 수 있고 이 노드들은 특정한 동작들을 수행한다.

![n8n node setting screen](_assets/attachments/괴담집/n8n-node-setting.png)

각각 연결된 노드들은 이전 노드에서의 결괏값을 input으로 가져올 수 있으며 이전 노드의 값을 json으로 변환하면 원하는 키값을 가져올 수 있다. 만약 json의 형태가 아니라면 `code`노드를 사용하여 `javascript` 혹은 `python`을 통해 정재하여 넘겨받을수도 있다.
또한 이전 노드가 아닌 현재 노드의 결괏값은 output으로써 node 설정창에서 값을 확인할 수 있다.

이렇게 들어오는 인풋과 아웃풋을 확인하여 개발해 나가는 형태는 `Jupyter`를 활용하여 개발해 나가는 느낌과 비슷하다. 디버그하기 매우 쉽고 편하다.

## 2. n8n 워크플로우 설정

### 2.1 API 사용을 위한 Credential 설정

n8n은 기본적으로 여러가지 플러그인을 지원하며 `Supabase`와 `Claude`도 지원한다. 이 노드들을 사용하기 위해선 API키 설정을 해주어야 하는데 n8n의 경우 간편하게 추가할 수 있는 설정 창이 있다.

화면 상단의 `+`를 클릭하면 드롭다운 메뉴가 나타나고 해당 메뉴에서 `Credential`을 선택한다. 이후 나타나는 검색 메뉴에서 `Supabase`, `Claude`를 검색하여 API키를 입력하면 된다.

![n8n credential adding screen](_assets/attachments/괴담집/n8n-credential-adding.png)

### 2.2 첫 노드 추가

`+`을 선택한 후 나타나는 드롭다운 메뉴에서 Workflow를 선택하면 본격적으로 워크플로우를 만들 수 있는 화면이 나타난다. 화면 중앙의 `Add first step`을 누르면 워크플로우가 트리거 되는 시작조건 노드를 추가할 수 있다.

![n8n first node](_assets/attachments/괴담집/n8n-first-node.png)

Schedule Trigger 노드의 경우 인터벌 설정을 통해 초,분,시간,일 등 여러 조건을을 설정하여 진행할 수 있게 매우 유연하다.

![schedule-trigger](_assets/attachments/괴담집/n8n-schedule-trigger.png)

### 2.3 AI 노드 추가

![n8n-ai-node](_assets/attachments/괴담집/n8n-ai-node.png)

AI를 사용하기 위해서 AI Agent 노드를 추가한다. 이 노드 아래 `Chat Model`과 `Memory`를 통해 기본적인 설정을 마칠 수 있다.

#### Agent 설정

만들어진 노드를 더블클릭 하면 프롬프트 설정이 가능하고 Add Option을 통해 시스템 프롬프트 설정도 가능하다.

![n8n-ai-agent-config](_assets/attachments/괴담집/n8n-ai-agent-config.png)

첫번째 설정인 Source for Prompt 의 값을 Define Below 값으로 바꿔 정적으로 동일한 메시지를 보내거나 이전 노드의 결괏값을 동적으로 보내는것이 가능 하다.

#### Claude 연결하기

![add llm](_assets/attachments/괴담집/n8n-add-llm.png)

`Chat Model`을 선택하면 사용 가능한 모델들이 나타나고 앞서 `Credential`을 추가한 Anthropic을 선택하면 자동적으로 API 설정이 완료 되어 사용 가능해 진다.

![n8n-ai-llm-config](_assets/attachments/괴담집/n8n-ai-llm-config.png)

`Chat Model`을 추가하면 나타나는 설정을 통해 다양한 설정이 가능한데 이 설정 옵션들은 모델들에 따라 다르다. `Anthropic`을 설정할때 중요한 요소는 개인적으로 토큰 값과 thinking 모드의 사용 유무 정도라고 생각한다.

#### Memory 사용하기

프로젝트에서 n8n 워크플로우의 역할은 지속적으로 다른 다양한 종류의 공포 이야기를 생성해 내는것이기 때문에 `Memory`의 사용이 굉장히 중요하다. 만약 `Memory`가 없다면 이전에 만들었던 이야기를 기억하지 못하기 때문에 비슷한 설정이 지속적으로 나올수도 있다.

![n8n memory](_assets/attachments/괴담집/n8n-ai-memory.png)

기본 메모리인 `Simple Memory`를 추가한다.

![n8n memory config](_assets/attachments/괴담집/n8n-ai-memory-config.png)

추가한 뒤 설정 창을 보면 Key값이 필요한것을 알 수 있다. 기본 설정값은 `Chat Input`을 위한 설정 값으로 `Chat Input`을 통해 대화를 시작할 시 output에 포함되는 `sessionId`를 사용하도록 하고 있다. 하지만 지금 프로젝트의 경우 고정된 값이 들어가야 하기 때문에 `sessionId`값을 따로 생성하지 않는다.

그렇기 때문에 키값을 수동으로 고정시켜 줘야 한다.

먼저 Session ID의 값을 Define below로 바꿔주고 Key값을 임의로 설정해준다.

### 2.4 RAG를 위한 Supabase 연결

n8n은 `Supabase`노드를 지원한다.

![n8n supabase get many](_assets/attachments/괴담집/n8n-supabase-getMany.png)

노드를 추가하고 get Many 옵션과 Retrun All 옵션을 통해 모든 결괏값을 가져올 수 있다.

#### Strapi의 관계형 데이터

프로젝트에 RAG를 위해 설정한 Collection은 관계형 데이터를 통해 Asset 에 Catetory와 Subcateogry 를 설정하고 있는데 기본적인 노드를 사용하면 해당 관계형 데이터 필드를 가져오지 못하는것을 확인했다.

이것을 해결하기 위해 `Claude`에게 물어보았고 SQL 함수를 생성하여 사용해야 한다는 답변을 받았다.

아래는 `Claude`가 알려준 생성 함수이다.

```sql
CREATE OR REPLACE FUNCTION get_assets_with_relations()
RETURNS JSON
LANGUAGE SQL
AS $$
  SELECT json_agg(
    json_build_object(
      'id', a.id,
      'document_id', a.document_id,
      'created_at', a.created_at,
      'updated_at', a.updated_at,
      'published_at', a.published_at,
      'created_by_id', a.created_by_id,
      'updated_by_id', a.updated_by_id,
      'locale', a.locale,
      'tag_name', a.tag_name,
      'display_name', a.display_name,
      'description', a.description,
      'usage_guide', a.usage_guide,
      'keywords', a.keywords,
      'implementation_type', a.implementation_type,
      'is_active', a.is_active,
      'categories', (
        SELECT json_agg(
          json_build_object(
            'id', c.id,
            'document_id', c.document_id,
            'name', c.name,
            'description', c.description
          )
        )
        FROM assets_category_lnk acl
        JOIN asset_categories c ON acl.asset_category_id = c.id
        WHERE acl.asset_id = a.id
      ),
      'subcategories', (
        SELECT json_agg(
          json_build_object(
            'id', sc.id,
            'document_id', sc.document_id,
            'name', sc.name,
            'description', sc.description
          )
        )
        FROM assets_subcategory_lnk asl
        JOIN asset_subcategories sc ON asl.asset_subcategory_id = sc.id
        WHERE asl.asset_id = a.id
      )
    ) ORDER BY a.id
  )
  FROM assets a;
$$;
```

이 함수를 사용하기 위해 Supabase에 접속하여 SQL Edittor을 사용하여 실행하였다.

![supabase sql function create](_assets/attachments/괴담집/supabase-sql-create.png)

이후 해당 함수를 불러와 테스트 해보면 된다.

```sql
SELECT get_assets_with_relations();
```

![sql functoin test](_assets/attachments/괴담집/sql-test.png)

### 2.5 RAG를 위한 JSON Formatting

RAG를 [[괴담집-공포 이야기 생성 프롬프트 v6-2]]에 적용하기 위해선 효과를 나타내는 부분을 실제로 DB에서 가져온 데이터로 대체해야 한다.

![n8n code node](_assets/attachments/괴담집/n8n-code-node.png)

입맛대로 문자열을 조작하기 위해서 앞선 `Supabase`노드 뒤에 `Code`노드를 붙혀 JSON 데이터를 정제할 수 있다. 이전 노드의 JSON 결괏값들을 쉽게 드래그해서 가져오고 문자열로 바꿔 정리해 새로운 프롬프트를 생성하면 된다.
